## 日本語スタイルガイドライン

Claude Codeが生成する日本語の可読性を高める。読者の負担を減らすための出力規則である。エージェントは以下のルールに従って日本語を出力する。

### 1. 1文1意
- 目的: 1文の中で主語と述語を一対一対応させる。
- 方法: 1文で伝える内容を1つに絞る。文を接続詞で長くつなげず、2文に分ける。
- 例: 「AでありBだがCとなる」を「Aである。しかしBのためCとなる。」とする。
- 基準: 1文の長さが概ね40〜60文字に収まっていること。

### 2. 肯定表現の優先
- 目的: 文章で説明する意図や動作を明確にする。
- 方法: 記述は可能な限り肯定文を優先する。「〜ではない」と表現したくなった場合、主体と動作の異なる複数の肯定文で同じ意味を表現できないか試みる。
- 例: 「このシステムはXXではなく、YYしない」→「このシステムはZZである。YYはシステムXXの役割である」
- 基準: 肯定文が大半を占め、否定文が1割未満であること。

### 3. 主体・対象・動作の明示
- 目的: 説明の対象を明確にする。
- 方法: 文章には明確な主語と対象を置く。述語は能動態で書き、具体的な動作・状態を説明する語を選ぶ。
- 例: 「柔軟性が高い設計にした」→「この設計は今後のXXなどの拡張を可能にする」(主体・対象・状態の明示)、「ここで処理Xが実行される」→「システムAが処理Bを実行する」(主体の明示)
- 基準: 文の主語が特定の主体であり、述語は具体的な動作・状態の説明であること

### 4. 情報の重複排除
- 目的: 情報な重複を省き、要点を簡潔に伝える。
- 方法: 同じ意味の言い換えを省く。前の文と重なる内容を削り、新しい情報で文を組み立てる。
- 例: 「この挙動は処理時間を短縮するための措置です。これにより実行速度が向上し、全体にかかる時間が短縮されます。」→「この挙動により全体の処理時間が短縮されます。」
- 基準: 文ごとに新しい事実や条件を1つ以上加わっていること。

### 5. 文末形式の機能的分離
- 目的: 本文の説明と読者への補足を区別する。
- 方法: 本文には「だ・である調」を使う。ユーザへの語りかけや補足には「です・ます調」を使う。同一の段落内では文末を統一し、役割が変わる箇所でのみ文末を切り替える。
- 例: 本文を「〜である / 〜だ。」とし、補足を「〜を参照してください。」とする。
- 基準: 事実や情報の説明の文末が断言調であること。ユーザへの依頼、補足等は敬体調であること。

### 6. 並列項目の構文統一
- 目的: 項目の比較を容易にする。
- 方法: 箇条書きで説明する場合、項目間で文末の品詞を揃える。
- 例: 「1. 速度向上 / 2. コストを減らす」→「1. 速度向上 / 2. コスト削減」のように体言止めで揃える。用言にする場合「1. 速度を上げる / 2. コストを減らす」。
- 基準: リスト内の項目が同一の語尾形式で揃っていること。
